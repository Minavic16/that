## Research Question

> Does conditional volatility in 4H FX markets contain stable,
> out-of-sample predictive information beyond simple causal volatility
> baselines, and if so, where can that information improve NestQuant?

This is NOT a question about whether GARCH works.
This is a question about whether conditional volatility structure exists
in FX 4H data and contains exploitable information.

---

## Why This Question Matters

If volatility structure exists and is predictable:
- NQTS position sizing can be improved (volatile regimes → smaller positions)
- Risk limits can be dynamic (not fixed 0.15%/trade)
- Circuit breakers can be volatility-aware
- Stop placement can adapt to current conditions
- Strategy selection can prefer low-volatility regimes

If volatility structure does NOT exist:
- We know the ATR in Strategy 1 is approximately optimal
- We can stop investigating volatility-dependent approaches
- We move to H1 (return predictability) with better understanding

Either outcome is valuable.

---

## Forecasting Target

Define precisely what we are forecasting:

**Target variable:** Realized volatility over the next N bars.

For 4H data, test multiple horizons:

| Horizon | Description | Relevance to NQTS |
|---|---|---|
| 1 bar (4h) | Next candle volatility | Intra-trade risk |
| 3 bars (12h) | Next trading session | Position sizing |
| 6 bars (24h) | Next day | Daily risk limits |
| 12 bars (48h) | 2-day horizon | Max hold period risk |

**Realized volatility estimator:**

```
RV_t = sqrt( (1/N) * sum( (r_t - r_bar)^2 ) )
```

where r_t are 4H log-returns within the measurement window.

Secondary estimator (more efficient):

```
Parkinson_RV = sqrt( (1/4N*ln2) * sum( ln(High/Low)^2 ) )
```

**Do NOT select the horizon that looks best.**
Test all horizons and report results for each.

## Baseline Models

Establish genuinely simple baselines before testing anything complex.
A model that cannot beat these baselines has no practical value.

### Baseline 1: Naive (Yesterday's Volatility)

```
sigma_hat_{t+1} = sigma_t
```

Just use the most recent realized volatility estimate.
This is the "do nothing" baseline.

### Baseline 2: Rolling Window

```
sigma_hat_{t+1} = mean( sigma_{t-W+1}, ..., sigma_t )
```

Average volatility over a lookback window W.
Test W ∈ {12, 24, 48, 96} (2-day, 4-day, 8-day, 16-day at 4H).

### Baseline 3: EWMA (Exponentially Weighted)

```
sigma_hat_{t+1} = sqrt( lambda * sigma_t^2 + (1-lambda) * sigma_{t-1}^2 )
```

Exponential moving average of squared returns.
Test lambda ∈ {0.90, 0.94, 0.97}.

These three baselines represent the minimum any model must beat.

## Test Models

### Model 1: GARCH(1,1)

The standard conditional volatility model.

```
sigma_t^2 = omega + alpha * epsilon_{t-1}^2 + beta * sigma_{t-1}^2
```

Parameters: omega, alpha, beta estimated by MLE.

Why test: Most common conditional volatility model. If this fails,
more complex models are unlikely to succeed at this timeframe.

### Model 2: GJR-GARCH(1,1)

Asymmetric GARCH capturing the leverage effect.

```
sigma_t^2 = omega + (alpha + gamma * I_{t-1}) * epsilon_{t-1}^2 + beta * sigma_{t-1}^2
```

where I = 1 if epsilon < 0 (bad news), 0 otherwise.

Why test: FX may show asymmetric volatility response to positive
vs negative returns. If gamma ≠ 0, this is evidence of leverage
effect in FX.

### Model 3: HAR-RV (Heterogeneous Autoregressive Realized Volatility)

Models volatility as a sum of short, medium, and long-term components.

```
RV_{t+h} = c + beta_s * RV_t(1d) + beta_m * RV_t(5d) + beta_l * RV_t(22d)
```

Why test: Captures long-memory in volatility, which GARCH cannot.
If HAR-RV outperforms GARCH, it suggests volatility has multi-scale
temporal structure.

### Model 4: Simple Regression (Feature-Based)

Test whether additional features improve volatility forecasts:

```
sigma_{t+1} = c + b1 * sigma_t + b2 * |r_t| + b3 * spread_t + b4 * day_of_week
```

Why test: Checks whether readily available features (return magnitude,
spread, time-of-week) improve forecasts. Low implementation cost,
high interpretability.

## Evaluation Framework

### Statistical Metrics

For each model × baseline × horizon × pair:

| Metric | What it measures | Formula |
|---|---|---|
| RMSE improvement | Forecast accuracy | 1 - (RMSE_model / RMSE_baseline) |
| MAE improvement | Robust accuracy | 1 - (MAE_model / MAE_baseline) |
| QLIKE | Volatility-specific loss | mean( log(sigma_model^2) + sigma_realized^2 / sigma_model^2 ) |
| Direction accuracy | Can we predict vol direction? | % correct sign of vol change |
| R² | Proportion of variance explained | 1 - SS_res / SS_tot |

**Improvement is relative to each baseline, not absolute.**

### Economic Metrics

| Metric | What it measures |
|---|---|
| Position sizing improvement | Would dynamic sizing improve risk-adjusted returns? |
| Risk limit accuracy | Would volatility forecasts reduce limit breaches? |
| Stop placement improvement | Would volatility-adaptive stops reduce false stops? |

Economic evaluation uses Strategy 1's existing signal framework:
- Take existing signals
- Apply volatility-adjusted position sizing
- Compare to fixed sizing

### Stability Criteria

Results must be stable across:

**Time:** Rolling 6-month windows. No single period should drive the result.
Report performance per window. Flag if >50% of improvement comes from one window.

**Pairs:** Test on all 20 pairs. Report per-pair results.
Flag if >50% of improvement comes from one pair.

**Volatility regimes:** Classify periods as low/medium/high vol.
Report per-regime results. Flag if improvement only exists in one regime.

## Walk-Forward Protocol

All evaluation must be strictly causal and walk-forward.

```
T=0: Train on data[0:T_train]
T=1: Forecast data[T_train+1]
T=2: Forecast data[T_train+2]
...
T=N: Forecast data[T_train+N]
T=N+1: Retrain on data[1:T_train+1]
T=N+2: Forecast data[T_train+N+2]
...
```

Parameters estimated on training window only.
No future data leakage.
No look-ahead in any forecast.

For each walk-forward step:
1. Estimate model parameters on training data
2. Generate forecast for next period
3. Compare to realized volatility
4. Record error
5. Advance window by 1 period

## Falsification Criteria

### Primary Falsification (H2 Dies)

H2 is falsified if ALL of the following are true:

1. No test model improves RMSE over the best baseline by more than
   the practical significance threshold (5%) on average

2. AND the improvement is NOT stable across:
   - At least 10 of 20 pairs
   - At least 3 of 4 time windows
   - At least 2 of 3 volatility regimes

3. AND direction accuracy is no better than 50% (coin flip)

If all three conditions hold: H2 is falsified. Archive and move to H1.

### Partial Falsification (Model Dies, Hypothesis Survives)

A specific model is falsified if:
- It does not improve over baselines
- But other models do improve

This is useful: it tells us which modeling approaches work and which
don't at this timeframe.

### Survival Criteria (H2 Survives)

H2 survives if ANY of the following hold:

1. At least one model improves RMSE by >5% over best baseline
   AND improvement is stable across pairs/time/regimes

2. OR direction accuracy is >55% AND stable

3. OR economic evaluation shows position sizing improvement
   AND the improvement is stable

"Stable" means:
- Present in >50% of pairs
- Present in >50% of time windows
- Present in >2 of 3 volatility regimes
- Not driven by a single outlier period or pair

### Expansion Criteria

Expand the investigation if H2 survives. Expansion includes:
- More pairs (add indices, commodities if data available)
- Higher-frequency data (if acquired)
- More sophisticated models (stochastic volatility, regime-switching)
- Cross-pair volatility spillover analysis
- NQTS integration assessment

## Output Classification

The final output must classify the finding per the Strategy 2 charter:

| Finding | Classification | Example |
|---|---|---|
| Volatility forecasts improve position sizing | **C: Risk Information** | Enters NQTS risk engine |
| Volatility forecasts predict returns | **A: Tradable Edge** | Strategy candidate |
| Volatility forecasts improve stops | **C: Risk Information** | Enters execution |
| Volatility forecasts identify regimes | **F: Regime Information** | Strategy selection |
| Volatility forecasts improve portfolio risk | **D: Portfolio Information** | Allocation |
| Models beat baselines but economically useless | **I: Interesting/Unusable** | Hold |
| Models don't beat baselines | **H: No Useful Information** | Archive |

The output is NOT "GARCH works/doesn't work."
The output IS "conditional volatility structure in FX 4H is/is not
detectable, and if detectable, it enters NQTS at [specific subsystem]."
